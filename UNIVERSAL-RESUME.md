# UNIVERSAL-RESUME.md — универсальная инструкция для возобновления работы в новом чате

> **Для владельца.** Этот файл не привязан ни к одному проекту. Если чат «умер»
> (среда не выполняет команды, контекст потерян, прошло много времени, началась
> новая сессия) — открой НОВЫЙ чат, вставь туда блок «КОМАНДА ВЛАДЕЛЬЦА» снизу,
> допиши токен и адрес репозитория — и любой ИИ-агент подхватит работу с места.
> Держи этот файл вместе с backups-файлами (BACKUP-BUNDLE и т.п.) или в корне
> рабочей папки: агент найдёт его сам.

> **Для агента.** Ты принимаешь проект после предыдущей сессии. Читай строго
> по шагам. Если у проекта есть СВОЯ инструкция (INSTRUCTIONS.md, AGENTS.md,
> README с разделом для агентов) — она ГЛАВНЕЕ этого файла; этот файл даёт
> только универсальный порядок возрождения и гигиену среды.

---

## 1. Шаг 0 — самопроверка среды (ДО всего, 1 минута)

Выполни лёгкую команду и посмотри на результат:

```bash
/bin/true && echo FORK_OK; df -h / | tail -1
n=0; t=0; for p in /proc/[0-9]*; do s=""; while IFS= read -r l; do case "$l" in "State:"*) s="$l";; esac; done < "$p/status" 2>/dev/null; t=$((t+1)); case "$s" in *Z*) n=$((n+1));; esac; done; echo "processes=$t zombies=$n"
```

* Всё выполнилось, зомби мало (< ~100) → среда жива, иди дальше.
* `fork: Resource temporarily unavailable` / команды виснут → **среда мертва**.
  НЕ крутись и НЕ обещай сборку: скажи владельцу ОДНУ фразу («среда исчерпана,
  нужны новые руки — открой новый чат и вставь команду»), работай только
  файловыми инструментами (читать/писать файлы можно без процессов) и оставь
  после себя обновлённый handoff-файл (раздел 6).

## 2. Шаг 1 — доступ и личность

1. Попроси у владельца ТОКЕН один раз (со scope, который нужен; обычно `repo`).
   Положи его только в `<корень workspace>/.git-credentials` (chmod 600) +
   `git config credential.helper "store --file …"`. НИКОГДА не печатай токен
   в чате, логах, коммитах, URL remote'а. Засветился → напомни отозвать.
2. Настрой git-личность владельца (имя/email из его аккаунта,
   `…@users.noreply.github.com`).
3. Проверь связь: клонирование или API-запрос к репозиторию.

## 3. Шаг 2 — найди проект и память прошлых сессий

Осмотри корень рабочей папки и прочитай ВСЁ, что похоже на память:

```
HANDOFF*.md  *RESUME*.md  INSTRUCTIONS.md  AGENTS.md  BACKUP-BUNDLE*.md
tools/  (gh-backup.sh, safe-edit.sh, .registry.tsv)  */.git/  uploads/
```

* Реестр бэкапов (`tools/.registry.tsv`, `<проект>/.git/BACKUP_REPO`) скажет,
  какая папка какому репозиторию соответствует.
* Handoff-файлы скажут, ЧТО было сделано и ЧТО осталось (незакоммиченные
  файлы, непроверенные сборки, незаменённые релизы).
* Ничего не нашлось → спроси у владельца адрес репозитория и задачу ОДНОЙ
  фразой; склонируй; дальше работай по репозиторию.

## 4. Шаг 3 — восстанови состояние «сделано / не сделано»

1. `git log --oneline | head`, `git status --short` — что закоммичено, что
   болтается в рабочей папке (это обычно и есть «не доделано»).
2. Релизы/теги/ветки через API: какие артефакты опубликованы, какого они
   поколения относительно кода (код новее артефактов = артефакты пересобрать).
3. Прогони быстрые тесты проекта, если они есть без тяжёлого окружения.
4. Скажи владельцу ОДНУ фразу: «подхватил то-то, осталось то-то».

## 5. Шаг 4 — работай по циклу (универсальному)

```
снимок ДО правок → правки → быстрые тесты → сборка → проверка сборки
→ коммит → пуш НА GitHub → замена/публикация релиза → отчёт владельцу
```

* Снимок до правок: бэкап-скрипт проекта (`gh-backup.sh snapshot …`) или,
  если его нет, ветка `savepoint-ГГГГММДД-ЧЧММСС` вручную.
* Пуш ДО того, как показать результат владельцу. Пуш не прошёл → скажи прямо.
* Ничего НЕ удаляй (файлы, релизы, репозитории, историю) без явной просьбы.
  Перезапись истории (force) — только с явного согласия владельца.
* Большие бинарники (>50 МБ) — не в git, а ассетами релиза.
* Секреты в коммиты не тащи (`.env`, ключи): они уже должны быть в .gitignore.

## 6. Шаг 5 — гигиена среды (чтобы чат не «умирал»)

* После КАЖДОГО тяжёлого шага (Wine, эмуляторы, Xvfb, браузеры, сборщики с
  демонами) убивай остатки: `wine64 wineserver -k; pkill -9 Xvfb` и т.п.
  Незакрытые пары «дисплей+сервер» и зомби накапливаются и убивают песочницу
  (признак: `fork: Resource temporarily unavailable`).
* Длинные сборки НЕ прерывай и не давай им виснуть: таймауты, лог в файл,
  проверка кода возврата. Прерванная сборка = мёртвая среда (см. шаг 0).
* Перед новой тяжёлой сборкой посчитай процессы (команда из шага 0):
  много зомби → сначала уборка, сборка в этой сессии невозможна → новый чат.
* Если среда умерла на середине: допиши handoff-файл (что готово, что нет,
  какие артефакты где лежат) файловыми инструментами — это спасёт следующую
  сессию, — и честно скажи владельцу менять чат.

## 7. Шаг 6 — память на будущее (механизм «Уроков»)

* В проекте должна жить инструкция для агентов (INSTRUCTIONS.md или этот файл,
  скопированный в репозиторий). В ней — раздел «Уроки (Lessons Learned)»:
  короткие правила вида **«если X → делай Y, иначе будет ошибка Z»**.
* Столкнулся с новой граблей → после решения допиши урок в конец раздела
  (нумерацию продолжай, старые не удаляй; устаревшие зачёркивай с датой).
* Обнови handoff-файл: «сделано / осталось / где артефакты» — актуальным
  состоянием на конец сессии.
* Закоммить и запушь оба файла вместе с результатом работы.

## 8. Шаг 7 — финал сессии

1. Пуш всего сделанного на GitHub (бэкап-скриптом или git'ом).
2. Отчёт владельцу: ОДНА человеческая фраза + ссылка (релиз/репозиторий).
   Владелец часто НЕ программист: без терминов, без списков из 20 пунктов.
3. Напомни отозвать токен, если он присылал его в чат.

## КОМАНДА ВЛАДЕЛЬЦА (вставь целиком в новый чат)

────────────────────────────────────────────────────────────────────────────
Ты принимаешь мой проект после предыдущей сессии, которая потеряла контекст
или умерла. Работай по файлу UNIVERSAL-RESUME.md (он в корне рабочей папки;
если его нет — выполняй шаги в том же порядке по памяти файла из репозитория).
Порядок строгий:

1. САМОПРОВЕРКА СРЕДЫ (шаг 0). Если среда мертва — скажи одну фразу и не трать
   время; обнови handoff-файл файловыми инструментами и предложи новый чат.
2. Запроси у меня недостающее: токен GitHub (пришлю отдельным сообщением),
   адрес репозитория (если не найдёшь в рабочей папке), задачу одной фразой.
3. Найди и прочитай память: HANDOFF*, INSTRUCTIONS.md, AGENTS.md, tools/,
   реестр бэкапов. Инструкция проекта главнее универсальной.
4. Восстанови «сделано / не сделано» (git log, git status, релизы через API)
   и скажи мне одну фразу, что подхватил.
5. Перед правками — снимок/бэкап-ветка. После работы — пуш на GitHub ДО того,
   как покажешь мне результат. Ничего не удаляй и не переписывай историю без
   моей явной просьбы. Большие файлы — ассетами релиза, не в git.
6. Гигиена среды: после каждого тяжёлого шага убивай остатки процессов;
   длинные сборки не прерывай; среда умерла → не повторяй попытки в ней,
   а открой новый чат и обнови handoff.
7. В конце: допиши новые «Уроки» (если X → делай Y, иначе Z) в инструкцию,
   обнови handoff, запушь всё и отчитайся мне одной фразой + ссылкой.
   Напомни отозвать токен.
